    <div className="smb-page-icon">🔀</div>
    <h1 className="smb-page-title">Use the Standard Model on your data</h1>
    <p className="smb-page-desc">
      This guide explains how to leverage the Standard Model on your own EHR data, including reshaping and tokenizing medical events, building a labels table, and training 4 types of classifiers on Standard Model embeddings.
    </p>
  </div>

  <p className="smb-p">The workflow consists of three stages:</p>

  <p className="smb-p">
    1. <strong>Format data and tokenize data:</strong> Organize your data into the required <a href="https://github.com/Medical-Event-Data-Standard/meds">MEDS</a> format to record medical <strong>events</strong> and a <strong>labels</strong> table which includes the ground truth for your task targets. Convert these into serial tokens using <code>smb_utils</code>.<br/><br/>
    2. <strong>Represent data as embeddings:</strong> Ingest MEDS <strong>events</strong> tokens into the Standard Model to produce high-dimensional patient-level embeddings.<br/><br/>
    3. <strong>Train clinical predictors:</strong> Use embeddings plus <strong>labels</strong> to train task heads (e.g., readmission, phenotyping, survival).
  </p>

  <div className="smb-callout smb-callout-check">
    Make sure you've completed the <a href="/">quickstart</a> setup. Commands below assume <code>quickstart/</code> as the working directory and use <code>uv run</code>.
  </div>

  {/* ==================== FORMAT + TOKENIZE ==================== */}

  <h2 className="smb-h2">Format and tokenize data</h2>

  <p className="smb-p">
    To apply the Standard Model, you must first have an <strong>events</strong> table in <a href="https://github.com/Medical-Event-Data-Standard/meds">MEDS (Medical Event Data Standard)</a> format (one row per clinical event). A collection of ETLs from common data formats, including OMOP, MIMIC-IV, and MEDS Unsorted can be found <a href="https://github.com/Medical-Event-Data-Standard/meds_etl">here</a>. The <a href="/example">end-to-end example</a> further describes the input data format.
  </p>

  <div className="smb-callout smb-callout-note">
    The Standard Model was built to operate on multiple modalities. For simplicity, this tutorial focuses on EHR text data. A more advanced multi-modal tutorial is forthcoming.
  </div>

  <p className="smb-p"><strong>Events data example rows:</strong></p>

  <div className="smb-table-wrap">
    <table className="smb-table">
      <thead>
        <tr><th>subject_id</th><th>time</th><th>code</th><th>table</th><th>value</th></tr>
      </thead>
      <tbody>
        <tr><td>10000032</td><td>2022-01-15 08:00:00</td><td><code>ICD10:I10</code></td><td>condition</td><td>—</td></tr>
        <tr><td>10000032</td><td>2022-01-15 09:30:00</td><td><code>LOINC:2093-3</code></td><td>lab</td><td>145.2</td></tr>
        <tr><td>10001217</td><td>2022-02-01 14:00:00</td><td><code>RxNorm:861004</code></td><td>medication</td><td>—</td></tr>
      </tbody>
    </table>
  </div>

  <p className="smb-p">
    You should also have a <strong>labels</strong> table with one row per subject, in the same order as your <strong>events</strong> table. Columns set the ground truth for prediction tasks, and are used for performance evaluation.
  </p>

  <p className="smb-p"><strong>Labels data example rows:</strong></p>

  <div className="smb-table-wrap">
    <table className="smb-table">
      <thead>
        <tr><th>subject_id</th><th>prediction_time</th><th>readmission_risk</th><th>phenotype_class</th><th>overall_survival_months</th><th>event_observed</th></tr>
      </thead>
      <tbody>
        <tr><td>10000032</td><td>2022-04-12 12:00:00</td><td>0</td><td>0</td><td>68.1</td><td>1</td></tr>
        <tr><td>10001217</td><td>2022-06-15 08:00:00</td><td>0</td><td>2</td><td>45.8</td><td>1</td></tr>
        <tr><td>10002428</td><td>2022-02-14 13:30:00</td><td>1</td><td>1</td><td>35.5</td><td>1</td></tr>
      </tbody>
    </table>
  </div>

  <p className="smb-p">
    Your <strong>labels</strong> should be derived from linked patient data and should reflect the data types used by your clinical outcome classifier or model type.
  </p>

  <p className="smb-p">
    The model tokenizer uses <code>prediction_time</code> in the <strong>labels</strong> table as the cutoff when considering events to build embeddings. Think of this date as the "as-of" time for the prediction, or the inclusive endpoint of data the model can use to generate embeddings.
  </p>

  <p className="smb-p">
    We next provide <code>smb_utils.process_ehr_info</code> to convert the MEDS <strong>events</strong> table into a tokenizable XML-like stream (e.g., [timestamp]: &lt;conditions&gt;&lt;/conditions&gt;, &lt;measurements&gt;&lt;/measurements&gt;).
  </p>

  <p className="smb-p">
    Time in our setting is measured in days. All events recorded at the same timestamp will be grouped by the event type/category with the XML-style tag, in chronological order. The timestamp is an explicit token in the string as well (see <code>input_text</code> in the example below).
  </p>

  <div className="smb-callout smb-callout-warning">
    Note that <code>smb-v1-1.7B</code> only supports a max token length of 4096, yet many patient histories exceed this constraint.<br/><br/>
    Our <a href="https://github.com/standardmodelbio/smb-utils">smb-utils</a> package offers functionality to solve this via multiple strategies as a temporary solution to efficiently manage context:<br/><br/>
    1. filter events data by modality (i.e., code or table columns),<br/>
    2. organize events into time bins with the most recent events from an anchor date, or<br/>
    3. flexibly define custom event categories.<br/><br/>
    Supporting longer context length is always a to-do on our list and we are almost ready to roll out something better pretty soon!
  </div>

  {/* ==================== ETL EXAMPLE ==================== */}

  <h3 className="smb-h4">ETL example</h3>

  <p className="smb-p">
    Assume your events are saved as <code>internal_cohort_meds.parquet</code> with the schema above. Load and verify, then serialize one patient:
  </p>

  <div className="smb-code-wrap">
    <div className="smb-code-label">python</div>
    <pre className="smb-code-block"><code>{`import pandas as pd
from smb_utils import process_ehr_info

# Load events (MEDS format: subject_id, time, code, table, value)
df = pd.read_parquet("internal_cohort_meds.parquet")
assert {"subject_id", "time", "code", "table", "value"}.issubset(df.columns)

# Example: Serialize a single patient history
# 'end_time' enforces causal masking (the model cannot see future data)
input_text = process_ehr_info(
    df,
    subject_id="patient_5521",
    end_time=pd.Timestamp("2024-01-01")
)

print(input_text)
# Output:
# [2023-11-15]
# <conditions>
# ICD10:C34.90
# </conditions>
# <medications>
# RxNorm:583214
# </medications>`}</code></pre>
  </div>

  <p className="smb-p">
    Labels must be aligned to the same patient order as your embedding matrix (i.e., same <code>subject_id</code> order as the events you passed to the model). This is important to resolve the correct <code>end_time</code> for each patient when creating embeddings.
  </p>

  <p className="smb-p">

  {/* ==================== REPRESENT AS EMBEDDINGS ==================== */}

  <h2 className="smb-h2">Represent data as embeddings</h2>

  <p className="smb-p">
    We now provide example code for <code>get_embeddings</code>, a function to load the model, serialize MEDS data into text, tokenize the text stream, and perform inference through the model for a full dataframe of patients.
  </p>

  <div className="smb-callout smb-callout-info">
    We use <strong>Last Token Pooling</strong> to extract the final hidden state, which represents the patient's entire causal trajectory up to the <code>end_time</code> (inclusive).
  </div>

  <div className="smb-code-wrap">
    <div className="smb-code-label">python</div>
    <pre className="smb-code-block"><code>{`import pandas as pd
import torch
from smb_utils import process_ehr_info
from transformers import AutoModelForCausalLM, AutoTokenizer
from tqdm import tqdm

MODEL_ID = "standardmodelbio/smb-v1-1.7b"

# 1. Load Model
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID, trust_remote_code=True, device_map="auto"
)
model.eval()

# 2. Batch Extraction (df from Format data step above)
def get_embeddings(df, pids, end_time):
    embeddings = []
    for pid in tqdm(pids):

        # Resolve per-patient end_time if a mapping is provided
        if isinstance(end_time, (pd.Series, dict)):
            patient_end_time = pd.Timestamp(end_time[pid])
        else:
            patient_end_time = end_time

        # A. Serialize (MEDS -> Text)
        text = process_ehr_info(df, subject_id=pid, end_time=patient_end_time)

        # B. Tokenize
        inputs = tokenizer(
            text, return_tensors="pt", truncation=True, max_length=4096
        ).to(model.device)

        # C. Inference (Hidden States)
        with torch.no_grad():
            outputs = model(inputs.input_ids, output_hidden_states=True)
            # Extract last token vector
            vec = outputs.hidden_states[-1][:, -1, :].cpu()
            embeddings.append(vec)

    return torch.cat(embeddings, dim=0).numpy()

# Execute
pids = df["subject_id"].unique()
# If your labels table has prediction_time
end_times = labels_df.set_index("subject_id")["prediction_time"]
X = get_embeddings(df, pids, end_times)`}</code></pre>
  </div>

  <p className="smb-p">
    The output <code>X</code> is a list of <strong>embeddings</strong> (fixed-length, 1-dimensional PyTorch tensor) that represent the patients' medical history from <code>df</code>. This list is in the same patient order as your MEDS data and labels table.
  </p>

  {/* ==================== TRAIN CLINICAL PREDICTORS ==================== */}

  <h2 className="smb-h2">Train clinical predictors</h2>

  <p className="smb-p">
    We can now use the embeddings (<code>X</code>) and the <strong>labels</strong> table to train multiple types of task heads to predict clinical outcomes.
  </p>

  <p className="smb-p">
    After importing the necessary packages and splitting our data into training and test sets, we complete <strong>Task A</strong>: a binary classifier to predict subject readmission to the hospital, as recorded in the <code>readmission_risk</code> column. ROC-AUC is given as the evaluation metric for Task A.
  </p>

  <div className="smb-code-wrap">
    <div className="smb-code-label">python — setup + task a</div>
    <pre className="smb-code-block"><code>{`# --- Setup ---
import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression, Ridge
from sklearn.model_selection import train_test_split
from sklearn.decomposition import PCA
from sklearn.metrics import roc_auc_score, accuracy_score, mean_absolute_error
from lifelines import CoxPHFitter

# X, pids from embedding step above. Load your labels table and align to X row order:
labels_df = pd.read_parquet("your_labels.parquet")  # replace with your path
labels = labels_df.set_index("subject_id").loc[pids].reset_index()

X_train, X_test, labels_train, labels_test = train_test_split(
    X, labels, test_size=0.2, random_state=42
)
print(f"Training on {len(X_train)} samples, testing on {len(X_test)}")


# --- Task A: Binary (Readmission Risk) ---
print("\\n--- Task A: Binary Classification ---")
clf_bin = LogisticRegression(max_iter=1000)
clf_bin.fit(X_train, labels_train["readmission_risk"])
y_prob = clf_bin.predict_proba(X_test)[:, 1]
auc = roc_auc_score(labels_test["readmission_risk"], y_prob)
print(f"-> ROC-AUC: {auc:.3f}")`}</code></pre>
  </div>

  <p className="smb-p">
    <strong>Task B</strong> is a multi-class classifier to predict cancer stage 1-4, as recorded in the <code>phenotype_class</code> column. Accuracy score, or fraction of correctly classified samples, is given as evaluation metric.
  </p>

  <div className="smb-code-wrap">
    <div className="smb-code-label">python — task b</div>
    <pre className="smb-code-block"><code>{`# --- Task B: Multiclass (Phenotype) ---
print("\\n--- Task B: Multiclass Phenotyping ---")
clf_multi = LogisticRegression(max_iter=1000)
clf_multi.fit(X_train, labels_train["phenotype_class"])
y_pred_class = clf_multi.predict(X_test)
acc = accuracy_score(labels_test["phenotype_class"], y_pred_class)
print(f"-> Accuracy: {acc:.3f}")`}</code></pre>
  </div>

  <p className="smb-p">
    <strong>Task C</strong> uses the continuous variable in <code>overall_survival_months</code> to train a regression model and predict months survival for subjects who died. Mean absolute error is reported for Task C.
  </p>

  <div className="smb-code-wrap">
    <div className="smb-code-label">python — task c</div>
    <pre className="smb-code-block"><code>{`# --- Task C: Regression (Survival months) ---
print("\\n--- Task C: Regression ---")
reg = Ridge(alpha=1.0)
reg.fit(X_train, labels_train["overall_survival_months"])
y_pred_reg = reg.predict(X_test)
mae = mean_absolute_error(labels_test["overall_survival_months"], y_pred_reg)
print(f"-> MAE: {mae:.2f}")`}</code></pre>
  </div>

  <p className="smb-p">
    Finally, <strong>Task D</strong> predicts the Cox proportional hazard between arbitrary groups of patients for risk of death, using the <code>overall_survival_months</code> and <code>event_observed</code> columns. The concordance index is reported as the evaluation metric.
  </p>

  <div className="smb-code-wrap">
    <div className="smb-code-label">python — task d</div>
    <pre className="smb-code-block"><code>{`# --- Task D: Survival (Cox PH) ---
print("\\n--- Task D: Survival Analysis ---")
pca = PCA(n_components=10)
X_train_pca = pca.fit_transform(X_train)
X_test_pca = pca.transform(X_test)
cox_df = pd.DataFrame(X_train_pca, columns=[f"PC{i}" for i in range(10)])
cox_df["T"] = labels_train["overall_survival_months"].values
cox_df["E"] = labels_train["event_observed"].values
cph = CoxPHFitter()
cph.fit(cox_df, duration_col="T", event_col="E")
test_cox_df = pd.DataFrame(X_test_pca, columns=[f"PC{i}" for i in range(10)])
test_cox_df["T"] = labels_test["overall_survival_months"].values
test_cox_df["E"] = labels_test["event_observed"].values
c_index = cph.score(test_cox_df, scoring_method="concordance_index")
print(f"-> C-Index: {c_index:.3f}")`}</code></pre>
  </div>
