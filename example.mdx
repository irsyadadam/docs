    <div className="smb-page-icon">🩺</div>
    <h1 className="smb-page-title">End-to-end example</h1>
    <p className="smb-page-desc">
      This demo illustrates the data formats, core functions, and results for using the <code>smb-v1-1.7b</code> model. The Python script loads MIMIC-IV demo data in MEDS format, extracts patient-representative embeddings using the Standard Model, and trains 4 example classifiers on those embeddings to predict clinical outcomes.
    </p>
  </div>

  <p className="smb-p">Two parquet files are used in the demo:</p>

  <p className="smb-p">
    1. An <strong>events</strong> table in <a href="https://github.com/Medical-Event-Data-Standard/meds">MEDS (Medical Event Data Standard)</a> format (one row per clinical event) used to create embeddings, and<br/>
    2. A <strong>labels</strong> table (one row per patient with task targets) used to record the clinical outcomes for the classifiers.
  </p>

  <p className="smb-p">
    This example contains a brief preview of each data file included in the demo, focused on the columns the model and classifiers use. We then give a description of how the demo script deploys the model to extract embeddings and provide clinical outcome predictions.
  </p>

  <div className="smb-callout smb-callout-info">
    This example uses the <a href="https://physionet.org/content/mimic-iv-demo-meds/">MIMIC-IV Clinical Database Demo</a> (a reduced, publicly available subset for teaching and development—not the full MIMIC-IV database) in MEDS format.
  </div>

  {/* ==================== SECTION 1 ==================== */}

  <h2 className="smb-h2">1. Events data (MEDS event stream)</h2>

  <p className="smb-p">
    The events file is a long table of timestamped clinical events (e.g. diagnoses, medications, labs). Although the <a href="https://physionet.org/content/mimic-iv-demo-meds/">MIMIC-IV Clinical Database Demo</a> parquet file contains other columns, <code>prep_mimic_demo_data.py</code> reshapes it to focus only those listed below for this demo. The final demo parquet file contains ~916k rows for 100 subjects.
  </p>

  <h2 className="smb-h2">2. Labels data (one row per subject)</h2>

  <p className="smb-p">
    The labels file contains columns recording the clinical outcomes for the four demo tasks we will predict, per subject. This will be used for training the classifiers and evaluating test prediction metrics.
  </p>

  <div className="smb-callout smb-callout-info">
    Outcome labels and <code>prediction_time</code> in this demo are <strong>artificially generated</strong> (see <a href="https://github.com/standardmodelbio/quickstart/blob/main/data/README.md">data/README.md</a> for methodology); they are not directly derived from events data and are for demonstration purposes only.<br/><br/>
    In a real use case, outcome labels should be directly derived from an events dataset, and <code>prediction_time</code> should be set as the timestamp strictly before the event that defines the label.
  </div>

  {/* ==================== RUNNING MANUALLY ==================== */}

  <h2 className="smb-h2">Running the demo manually</h2>

  <p className="smb-p">
    Running <code>demo.py</code> loads both pre-configured data files from the <a href="https://github.com/standardmodelbio/quickstart">quickstart repo</a> (main branch) into memory, then:
  </p>

  <p className="smb-p">
    1. <strong>Events → Embeddings:</strong> For each patient, it serializes that patient's events (using <code>subject_id</code>, <code>time</code>, <code>code</code>, <code>table</code>, <code>value</code> from the events data) into a token stream with <code>smb_utils</code> up to <code>prediction_time</code> from the labels file. The script then runs the Standard Model, and takes the last-token hidden state as the <strong>patient embedding</strong>.<br/><br/>
    2. <strong>Embeddings + Labels → Predictive Task Performance Metrics:</strong> After extracting embeddings, <code>demo.py</code> trains four separate task heads designed to predict A) binary hospital readmission, B) multiclass classification of cancer staging, C) continuous survival regression in months, and D) Cox survival. Each predictive output layer is trained on an 80/20 train/test split of the embeddings and labels. ROC-AUC, accuracy, mean absolute error, and C-index are provided for each of these tasks, respectively.
  </p>

  <p className="smb-p">
    If you ran the <a href="/">quickstart</a> model installation, you can run the demo with:
  </p>

  <div className="smb-code-wrap">
    <div className="smb-code-label">bash</div>
    <pre className="smb-code-block"><code>{`cd quickstart
uv run python demo.py`}</code></pre>
  </div>
